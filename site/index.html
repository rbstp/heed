Heed

Focus follows mouse for macOS, and movefocus to go with it.

Heed moves keyboard focus to the window under the pointer, after Hyprland's follow_mouse and movefocus. It runs in the background with no Dock icon and no main window; a menu bar icon and a global hotkey turn it on and off. macOS 14 or later, Apple Silicon.

$ brew install --cask rbstp/tap/heed
Download the archive MIT Swift 6 Signed and notarized

follow_mouse

The window under the pointer gets the keyboard.

Move the mouse into a window and it has focus. Nothing is raised across applications, because macOS does not separate the two; within an app, the raise setting decides.

Click the mark in the menu bar to turn it on or off, or press ⌃⌘H from anywhere. A filled core means on; the chevrons alone mean off. A dim mark means Heed cannot work yet, and hovering says why.

focus fights

Follows the pointer, but not into a fight.

  • Typing, clicking, dragging, open menus and Command-Tab suppress pointer focus briefly.
  • Dialogs, About windows and prompts keep their focus until answered.
  • A window that appears under a still pointer does not take focus.
  • Focus that arrived by shortcut, launch or menu stays put until the pointer rests on another window. Crossing the menu bar or empty space does not release it.
  • Small movement does not count as settling. Floating panels are not targets.

movefocus

Shortcuts, whether Heed is on or off.

⌃⌘H
Turn focus following on or off.
⌃⌘→ ←
Next or previous visible window, screen by screen from left to right, then left to right within each screen.Spatial order, not stacking order: stepping through does not reorder the cycle. Windows completely covered by others are skipped.
⌃⌘1 to 9
The window with that number, counted in the same order. With Zen on the left and a terminal on the right, 1 is Zen and 2 is the terminal.
Hold ⌃⌘
Each window shows its number on screen, so the digit can be read rather than counted.They appear after a tenth of a second, so a shortcut typed at speed does not flash them. Try it on this page.
Right-click the mark
Change the modifier of every shortcut at once, switch the window numbers off, open the log, see the version, or quit.

Heed registers hotkeys exclusively, so a combination it claims is gone from every other app. Shortcut Modifier in the menu flashes the icon green when a change takes and red when the combination is taken; the log says which app holds it.

window numbers

Numbers you can read instead of count.

Hold the numbered shortcuts' modifier on its own and every window is labelled on screen. This page does the same: hold ⌃⌘ and the tiles number themselves, then press a digit.

On by default. Show Window Numbers in the right-click menu turns it off, and windowNumbersDelayMs sets how long the hold must be.

directional

Left, right, up, down.

Move to the nearest window in a direction. A window sharing a row or column with the focused one wins over a closer one that does not, and the edge of the arrangement is a dead end rather than a wrap.

Off by default, because every shortcut Heed registers is taken from every other app. WASD rather than HJKL, since the toggle is already on H:

# pair it with a tiling shortcut: Raycast's halves and quarters
# put the windows where these then move between
defaults write io.github.rbstp.heed focusLeftHotkey  'cmd+ctrl+alt+a'
defaults write io.github.rbstp.heed focusDownHotkey  'cmd+ctrl+alt+s'
defaults write io.github.rbstp.heed focusUpHotkey    'cmd+ctrl+alt+w'
defaults write io.github.rbstp.heed focusRightHotkey 'cmd+ctrl+alt+d'
make restart

mouse follows focus

Turn it around: the pointer follows focus.

Focus moved by keyboard leaves the pointer over the window you just left, and the next flick of the mouse drags focus back there. With warpPointer on, the pointer follows focus into the new window instead, on Command-Tab, on the focus shortcuts, on a window picked from Raycast's Switch Windows, and on any other keyboard-driven activation.

It does not move for a click, mid-drag, into a window Heed would not focus by pointer, or when the pointer is already inside. warpX and warpY place it inside the window as percentages; the default is the centre.

defaults write io.github.rbstp.heed warpPointer -bool true
make restart

heed://

Drive it from somewhere else.

Every shortcut Heed registers is taken from every other app, so it can also be driven without registering anything. A URL reaches the running agent directly, and the same vocabulary works as flags on the installed binary.

open 'heed://focus/next'
open 'heed://focus/left'
open 'heed://focus/3'
open 'heed://toggle'        # also enable, disable

~/Applications/Heed.app/Contents/MacOS/Heed --focus next
~/Applications/Heed.app/Contents/MacOS/Heed --windows   # the focus ring as JSON

Window numbers past 9 work here even though the shortcuts stop at the digit keys. heed://focus/id/<n> takes the window server's own number instead, the id field of --windows: a place in the ring is only true of the ring it came from, and Heed rebuilds that ring every time.

The flags reach the agent over a distributed notification, which any process in your login session can post. The vocabulary is fixed at toggle-and-focus: no arbitrary arguments, no window contents, nothing read back. If that is not a trade you want, use the hotkeys; nothing else in Heed listens.

raycast

Let Raycast own the hotkey.

Raycast already tiles and switches windows; Heed adds the pointer. The Raycast extension has a command for each focus move and for the toggle, so the hotkey is Raycast's and Heed claims nothing.

Or without it: a Quicklink to heed://focus/next with a hotkey, then free the combination Heed holds with defaults write io.github.rbstp.heed focusNextHotkey ''.

Restart Heed after changing them: make restart from a checkout, or quit and relaunch. Heed always excludes itself, Dock, WindowServer, loginwindow, Control Center, Notification Center, SystemUIServer, the screenshot UI, Spotlight, Raycast and AltTab.

troubleshooting

See what Heed sees.

On first launch, grant Heed access in System Settings › Privacy & Security › Accessibility. It picks the grant up without a restart. Releases from 0.12.0 on are signed with a Developer ID and notarized, so the grant carries across versions; only an upgrade from an older ad-hoc build needs it reset.

make probe                 # what is under the pointer
make probe X=960 Y=540     # or at a point
defaults write io.github.rbstp.heed verbose -bool true
make restart && make logs  # per-decision logging
tccutil reset Accessibility io.github.rbstp.heed

Every release archive carries a build provenance attestation, so a download can be traced back to the commit and workflow run that produced it: gh attestation verify Heed-0.12.3.zip --repo rbstp/heed.

limitations

What it cannot do.

  • Focusing another application raises it. macOS does not separate the two.
  • Apps with incomplete Accessibility support may only work at application level. Some games, XQuartz and Java applications expose no individual windows: the pointer focuses them as a whole, and the focus shortcuts skip them.
  • Stage Manager may override window ordering.

about
